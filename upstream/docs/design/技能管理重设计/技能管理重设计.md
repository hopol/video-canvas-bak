## 1. 设计摘要

**问题**：

1. 一个技能「在哪里能被用到」被拆成两处、两套保存方式：启用开关在概览顶部、点了**立即生效**；短剧适用环节在概览最底部，要另点「保存」。同一页两种保存规则，而且最重要的信息被放在最不显眼的位置。
2. 环节胶囊没选中时和普通按钮长得一样，看不出它是可多选的开关；保存按钮灰着孤零零吊在下面。
3. 「启用」隐含了「进画布 Agent」，没办法让技能**只给短剧用**。
4. 概览页信息重复、空间浪费：显示名和技能名经常一样；「头部字段」又把 name / description 列一遍；状态卡、版本卡大半是空白。
5. 28 个文件的技能包塞在弹窗里看，文件树和预览都挤；详情没有地址，刷新就丢、不能把链接发给同事。

**目标**：管理员一眼看清每个技能用在哪些地方，在一个地方、用一种规则（开关即时生效、可撤销）改它；技能内容（文件、版本）有足够空间看。

**推荐结论**：

| 决策 | 结论 | 依据 |
| --- | --- | --- |
| 使用范围模型 | **各场景独立开关**：画布 Agent、剧本改编、资产拆解、资产图提示词、视频提示词，五个开关互不依赖；技能可以只给短剧用 | 用户回答 Q1 |
| 保存方式 | 每个开关**点了立即生效**，成功后 toast 带「撤销」；去掉「保存」按钮 | 与现有启停一致（`use-agent-skills.ts` `toggleEnabled`）；NN/G 开关指南 |
| 详情形态 | **独立详情页** `/admin/agent/skills/:name`：主区放「文件 / 版本」，右侧栏放「用在哪里」和信息 | 用户回答 Q2 |
| 列表 | 行末单个启用开关换成**场景标签列**；筛选改为「全部 / 画布 Agent / 短剧 / 未使用 / 内置」；改范围要进详情页 | 用户回答 Q3 |
| 导入衔接 | 导入第 2 步（检查并确认）底部可**顺手勾场景**，默认都不勾；导入新版本时不出现 | 用户回答 Q4 |
| 内置技能 | **继续全只读**：画布 Agent 固定开、短剧四环节固定关，开关置灰、悬停写原因 | 用户回答 Q5 |

### 2.2 设计约束

- 后台新行为写进 `components/admin-ui`，不改共享 `components/ui`（项目记忆：后台 / 画布 UI 分开维护）。
- 不加说明小字：「用在哪里」靠分组标题和开关本身说话，禁用原因放悬停提示。
- 技能版本不可变；「用在哪里」与版本无关，是技能级状态（与 `enabled`、`drama_steps` 现状一致）。
- 短剧的拼接规则不变：技能正文作为「写作方法」注入，脚本不执行，`has_scripts` 的技能在短剧侧标「仅用正文」（[短剧开拍设置.md](../短剧开拍设置/短剧开拍设置.md) §6.7）。

### 2.3 当前缺口

- 没有「只给短剧用」的表达：短剧下拉要求 `Enabled`，而 `Enabled` 必然进画布 Agent。
- 列表看不出技能被用在哪个短剧环节。
- 详情没有 URL。

## 3. 用户与场景

- **用户**：运营管理员（`admin` / `super_admin`），低频但集中地操作：导入一批技能 → 决定各自用在哪里 → 偶尔换版本、下线。
- **主任务**：
  1. 导入一个新技能，确定它用在哪里（一次完成）。
  2. 运营反馈「短剧资产拆解效果差」→ 在列表按「短剧」筛选 → 找到挂在资产拆解上的技能 → 关掉或换版本。
  3. 导入新版本 → 对比文件 → 设为生效。
- **成功指标**（提案）：从列表到改完一个技能的使用范围 ≤ 2 次点击 + 1 次开关；页面上不再有「保存」按钮；列表不进详情就能回答「这个技能用在哪」。

## 5. 设计原则

1. **一种保存规则**：会改变线上行为的控件全部是即时开关，成功给「撤销」；页面上没有「保存」按钮（NN/G；现有 `toggleEnabled`）。
2. **范围是一等信息**：「用在哪里」在列表有列、在详情首屏常驻，不藏在滚动底部（问题 1；Claude 管理员后台）。
3. **场景各自独立**：画布 Agent 和短剧环节平级，互不依赖，没有「总开关」（用户回答 Q1；扣子的分层启停）。
4. **内容和设置分区**：主区看技能内容（文件、版本），侧栏管设置（范围、信息），危险操作收进菜单。
5. **不重复展示**：显示名等于技能名时只显示一次；头部字段只在文件预览里出现。
6. **禁用不隐藏**：不可用的开关置灰并在悬停写原因（项目已有 `ReasonTooltip` 做法）。

## 6. 推荐方案

### 6.1 信息架构

```
后台 / AI 配置 / 技能                      /admin/agent/skills
├─ 页头：标题「技能」 + [导入技能]
├─ 工具条：搜索（/） · 筛选 全部|画布 Agent|短剧|未使用|内置 · 共 N 个
├─ 列表：技能 | 说明 | 用在哪里 | 版本 | 更新
└─ 导入对话框（两步，居中）—— 第 2 步底部新增「用在哪里」

技能详情                                  /admin/agent/skills/:name
├─ 页头：← 技能 · 图标 · 显示名(可改) · 技能名(与显示名不同时) · 来源标签 · [⋯]
│        [⋯] = 下载生效版本 / 删除技能
├─ 待生效横幅（有更新版本未生效时）：v3 已导入，尚未生效  [对比文件] [设为生效]
├─ 主区（左，自适应）
│   └─ 页签：文件 | 版本 N
└─ 侧栏（右，320px；< 1024px 时移到页签上方）
    ├─ 卡片「用在哪里」
    │   ├─ 画布          画布 Agent              [开关]
    │   └─ 短剧工作室    剧本改编 / 资产拆解 / 资产图提示词 / 视频提示词   [开关]×4
    │                   （has_scripts 时分组标题旁标「仅用正文」）
    └─ 卡片「信息」：说明（4 行折叠） · 生效版本 · 内容 · 更新时间 · 未支持字段（有才显示）
```

**变更**：去掉「概览」页签、状态卡、生效版本大数字卡、「头部字段」区块、「危险操作」区块。头部字段在「文件」页签打开 `SKILL.md` 时已由 `FrontmatterCard` 展示（`file-preview.tsx`），不再重复。

### 6.2 列表页

| 列 | 内容 | 说明 |
| --- | --- | --- |
| 技能 | 图标块 + 显示名；显示名 ≠ 技能名时下面一行等宽小字技能名；内置技能名后带「内置」标签 | 修正现状「两行一样」 |
| 说明 | 两行截断 | 不变 |
| 用在哪里 | 清透小标签：`画布 Agent`、`改编`、`拆解`、`资产图`、`视频`，按固定顺序；一个都没有时灰字「未使用」 | 标签只读，悬停显示全称（如「短剧 · 资产图提示词」） |
| 版本 | `v2`；有待生效版本时右侧琥珀 `v3 待生效` | 沿用 `versionBadge` |
| 更新 | 相对时间（「3 天前」），悬停绝对时间 | 默认值 |

- 去掉「来源与内容」列：来源改成名称旁的「内置」标签（导入是默认，不标），文件数进详情。
- 去掉行末启用开关：范围改在详情里（用户回答 Q3）。
- 整行是 `<Link>`：点击进详情，⌘ / Ctrl + 点击新标签打开；Enter 进入。
- 筛选：`全部 / 画布 Agent / 短剧 / 未使用 / 内置`。「短剧」= 任一环节开；「未使用」= 导入技能且五个开关全关。
- 窄屏（< 768px）卡片：名称 + 版本 / 说明 / 场景标签。
- 新导入的行沿用现有一次性紫色高亮 `FRESH_ROW`。
- 从详情返回时恢复列表的搜索、筛选和页码（默认值：列表状态放 URL 查询参数，返回用浏览器后退；直接打开详情时「← 技能」回到无参数列表）。

### 6.3 详情页

**页头**

- 「← 技能」返回。
- 显示名：点铅笔原地改（沿用 `TitleField`：Enter 保存、Esc 取消，≤ 64 字）；内置技能无铅笔。
- 技能名等宽小字：仅当与显示名不同时显示，带复制按钮。
- 右侧摘要：`在用 3 处` / `未使用`（中性灰）。
- `⋯` 菜单：下载生效版本（zip）、删除技能（红色）。内置技能菜单只有「下载」不可用 → 整个菜单隐藏。

**待生效横幅**（`pending_version = true` 时）：`v3 已导入，尚未生效`，按钮 [对比文件]（切到文件页签并选中 v3）和 [设为生效]（即时，toast 带撤销 = 设回原版本）。

**右侧栏「用在哪里」**

- 五行，每行：场景名 + 开关，行高 ≥ 44px，整行可点（点行 = 点开关）。
- 分组标题「画布」「短剧工作室」，不写说明小字。
- `has_scripts` 的技能在「短剧工作室」标题旁标 `仅用正文` 标签（悬停：「短剧只注入正文，不执行脚本」）。
- 禁用与原因（悬停 `ReasonTooltip`）：
  - 内置技能：五个都禁用，「内置技能随版本发布，不能修改」。
  - 没有生效版本、且当前是关：「没有生效版本，无法启用」；已开的允许关。
  - 正在请求的那一行：开关显示加载态并禁用，其他行可继续点（逐个排队，见 §7）。

**右侧栏「信息」**：说明（超过 4 行折叠「展开」）、生效版本 `v2 · 共 3 个版本`、内容 `28 个文件 · 279.9 KB`、更新时间、未支持字段（有才显示，琥珀标签列出字段名）。

**主区页签**

- 「文件」：沿用 `FileWorkbench`，上方版本切换（`Segmented`）+ 下载整包；整页高度，文件树和预览都不再挤。
- 「版本 N」：沿用 `VersionTimeline`（设为生效 / 回滚、看文件、下载、删除）。
- 当前页签记在 URL 查询参数 `?tab=versions&v=3`（默认值），刷新不丢。

### 6.4 导入对话框

- 两步流程、预检横幅、左右分栏都不变。
- 第 2 步、且 `plan.action = create` 时，底部按钮条左侧多一组「用在哪里」五个小开关（`ToggleChip` 多选，默认全不选），右侧仍是 [重新选择] [确认导入]。
- `plan.action = new_version` 时不出现（新版本不自动生效，范围沿用技能现有设置，`plan.enabled` 现有提示保留）。
- 确认导入时把选中的范围一起提交（§8.2）；导入后回到列表、高亮新行；toast：「已导入「X」，用在 2 处」或「已导入「X」，暂未使用」。

## 7. 状态与异常

| 场景 | 行为 |
| --- | --- |
| 详情加载中 | 页头和侧栏骨架；超过 150ms 才显示骨架（沿用 `SKELETON_DELAY`） |
| 技能不存在（被删 / 链接错） | 空状态「技能不存在或已删除」+ [返回技能列表] |
| 详情加载失败 | 空状态「技能加载失败」+ [重试] |
| 开关点下 | 乐观翻转 → 请求 → 成功 toast「已在「剧本改编」启用「X」」+ 撤销（6 秒，沿用 `UNDO_MS`） |
| 开关失败 | 翻回原状态，全局错误 toast 已弹（沿用 API 层约定） |
| 连续快速点多个开关 | 同一技能的请求串行排队；每次请求带完整的目标状态（画布 Agent 用 `enabled`，短剧用完整 `steps`），后到的覆盖先到的，不会丢改动 |
| 撤销 | 发一次反向请求，与普通开关同一队列 |
| 另一个管理员同时改 | 后写覆盖（与现状一致，范围设置无版本号）；每次请求成功都用返回的技能视图刷新本地 |
| 没有生效版本 | 关着的开关禁用并写原因；可以关 |
| 删除技能 | `⋯ → 删除技能` → 删除预检 → 确认框；有任何场景开着时确认按钮禁用，原因「请先关闭所有使用场景」；成功后回列表 + toast |
| 删除生效版本 | 不变：生效版本不能删 |
| 内置技能 | 只读：开关、改名、删除都不可用并写原因 |
| 导入时勾了场景但技能创建失败 | 整个确认失败，不会出现「技能建了范围没设」的半成品（后端同一事务，§8.2） |

## 8. 数据与工程影响（提案）

### 8.1 语义调整（不加列）

| 字段 | 现在 | 改为 |
| --- | --- | --- |
| `agent_skills.enabled` | 「启用」：进画布 Agent，且是短剧可见的前提 | **仅表示「画布 Agent」开关**；不再影响短剧 |
| `agent_skills.drama_steps` | 标了且 `enabled` 才在短剧可见 | **标了且有就绪生效版本**就在短剧对应环节可见 |

- `DramaSkills`：条件由 `Enabled && ActiveVersion != nil && contains` 改为 `ActiveVersion != nil && ready && contains`。
- `SetDramaSteps`：新增检查——新增的环节需要就绪生效版本，否则 61009（与 `SetEnabled` 同码）；只减不增时不检查。
- 删除预检：`CanDelete = !Enabled && len(DramaSteps) == 0`，原因文案「请先关闭所有使用场景」。
- 列表项新增派生字段 `in_use: bool = enabled || len(drama_steps) > 0`（不落库，方便前端和筛选）。
- 前端类型注释同步：`enabled` 改为「是否在画布 Agent 中可用」。

**数据迁移**（一次性，避免上线后突然冒出短剧技能）：

```sql
-- 现在停用但标了环节的技能，上线前对用户不可见；迁移后保持不可见
UPDATE agent_skills SET drama_steps = '[]' WHERE enabled = false AND drama_steps <> '[]';
```

推断：迁移后「启用 + 标了环节」的技能行为不变（仍同时在画布 Agent 和短剧）；管理员可以之后单独关掉画布 Agent，实现「只给短剧」。

### 8.2 接口变化

| 接口 | 变化 |
| --- | --- |
| `GET /admin/agent/skills` | `status` 取值改为 `agent | drama | unused | builtin`（不传 = 全部）；旧值 `enabled` 视同 `agent`、`disabled` 视同 `unused` 兼容一个版本；返回项加 `in_use` |
| `PUT /admin/agent/skills/:name/enabled` | 不变，界面叫「画布 Agent」 |
| `PUT /admin/agent/skills/:name/drama-steps` | 请求不变（整组覆盖）；新增 61009；审计不变 |

| `GET /admin/agent/skills/:name/delete-check` | `can_delete` 规则见 §8.1 |
| `GET /drama-skills?step=` | 返回条件见 §8.1，响应结构不变 |

错误码沿用：61007 内置技能只读、61009 没有生效版本、10001 参数错。

## 9. 方案取舍

默认权重（用户未单独排序，按访谈倾向推定）：一眼看清 30%、规则一致 25%、只给短剧用 20%、内容空间 15%、实现成本 10%。

| 方案 | 一眼看清 | 规则一致 | 只给短剧 | 内容空间 | 成本 | 加权 |
| --- | --- | --- | --- | --- | --- | --- |
| **推荐：独立详情页 + 场景开关** | 5 | 5 | 5 | 5 | 3 | **4.8** |
| 备选 A：保留弹窗，环节改即时开关并上移 | 3 | 5 | 1 | 2 | 5 | 3.2 |
| 备选 B：右侧抽屉 + 场景开关 | 4 | 5 | 5 | 2 | 4 | 4.2 |

**明确放弃**：

- 列表上直接勾场景矩阵（信息密、易误点；用户选了只读标签）。
- 总开关 + 子开关（多一层心智，用户选了平级独立）。
- 「全部环节」快捷项：只有四个环节，逐个开更清楚（调研启发里的「默认 + 例外」对我们过重）。
- 显式「保存」按钮（与即时开关冲突）。
