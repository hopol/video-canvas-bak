技能管理重设计

把「启用」和「短剧环节」合成一组「用在哪里」

现在一个技能用在哪，被拆成顶部的启用开关（点了就生效）和底部的环节胶囊（还要另点「保存」）。新设计里，画布 Agent 和短剧四个环节是五个平级开关，每个点了立即生效、可以撤销，页面上不再有「保存」按钮；技能可以只给短剧用。详情从弹窗改成独立页面，列表直接显示每个技能用在哪。

运营说「短剧资产拆解效果差」时，会发生什么

新设计下排查和处理的完整路径，以及一个要提前说清的边界。

  1. 列表筛选「短剧」标签列里带「拆解」的就是挂在资产拆解上的技能
  2. 点进详情侧栏看到它同时开着画布 Agent 和资产拆解
  3. 关掉「资产拆解」立即生效，toast 可撤销；画布 Agent 不受影响
  4. 或切到「版本」换回旧版设为生效同样即时、可撤销
边界：已经开拍的剧不受影响
  • 用户开拍时提示词是快照，关掉环节后已有剧照常用旧快照，界面在该行标「来源已停用」（短剧开拍设置已有的 missing 行为）。
  • 新开拍的剧下拉里不再出现这个技能。

上线时要告诉运营：迁移会把「停用但标了环节」的技能的环节清空（它们本来对用户不可见），之后需要的话重新打开。

// 前端：同一技能的场景开关串行提交（提案）
toggleScope(item, scope, on):
  local = optimistic(item, scope, on)          // 立即翻转
  queue[item.name] = queue[item.name].then(async () => {
    const next = scope === "agent"
      ? await setSkillEnabled(item.name, local.enabled)
      : await setSkillDramaSteps(item.name, ordered(local.drama_steps))   // 带完整目标状态
    replaceOne(next)
    toast(`已在「${label(scope)}」${on ? "启用" : "停用"}「${next.title}」`, { action: 撤销 → toggleScope(next, scope, !on) })
  }).catch(() => rollback(item, scope))         // 全局错误 toast 已弹
