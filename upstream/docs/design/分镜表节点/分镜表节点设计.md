# 分镜表节点设计

> 对应 PRD：`/Users/Zhuanz/DS Bot/分镜表节点PRD.md` 第 6.1–6.7 节；可交互原型：[分镜表节点-演示.html](分镜表节点-演示.html)。
> 范围：§1–§5 为迭代 1（节点卡片、表格编辑区、空状态、下拉控件、行操作）；§6 为迭代 2（拆分镜、按行生成分镜图 / 视频、分镜图上传）。
> 视觉沿用现有画布：`NodeCard` / `BaseNode` 外壳、主题变量（`--card`、`--chrome*`、`--node-ring`），浮层遵守 `web/docs/coding-standards.md` 6.1–6.3。

## 1. 编辑区形式：选「大弹窗」

| 方案 | 优点 | 问题 | 结论 |
|---|---|---|---|
| 节点内展开 | 不离开画布 | 画布缩放后字跟着变小、没法打字；8 列 × 50 行把节点撑到几千像素，压住别的节点；滚轮和画布缩放抢事件；50 行全部挂在 React Flow 节点里，拖画布会卡（AC13） | 不选 |
| 侧边抽屉 | 能同时看到画布 | 宽度最多 ~720px，放不下 8 列，只能横向滚或把每行折成卡片，看不到全局，和「一行一镜看全局」的目标冲突 | 不选 |
| **大弹窗** | 宽度够放下 8 列，一屏能看 8–10 镜；和现有文本节点、角色详情、提示词弹窗的打开方式一致（双击节点打开）；不受画布缩放影响 | 编辑时看不到画布 | **选它** |

「看不到画布」的影响很小：迭代 1 只编辑表格；迭代 2 生成的图片、视频结果会回填到行里（分镜图单元格、视频状态），在弹窗里就能看到，不用回画布找。

尺寸：`w-[min(1280px,94vw)]`、`h-[min(88svh,860px)]`，标题栏和底栏固定，表格区内部滚动（规范 6.3）。弹窗常驻挂载，用 `open` 开关。

## 2. 节点卡片

固定 576 × 324（16:9），和 16:9 的图片节点同一个来源（`nodeFrameSize(DEFAULT_NODE_ASPECT)`，短边 324），也是新建节点和自动排版预留的默认尺寸，沿用 `NodeCard`。框里放不下的镜头少显示几行，不撑大卡片，空状态在框内居中：

- **标题行**（卡片上方，NodeCard 自带）：图标 + 名称（双击改名）；右侧 `status` 槽位放统计「12 镜 · 01:24」，`text-muted-foreground tabular-nums`。
- **图标**：lucide `GalleryHorizontalEnd`（导演台已用 `Clapperboard`，避免撞）。
- **缩略图条**：一行 5 格 16:9 小画格，`rounded-sm`，间距 6px；超过 5 镜时最后一格叠 `+N`。迭代 1 没有分镜图，画格显示镜号 + 景别（`bg-muted` 底，镜号大字）。迭代 2 有图后直接显示图。
- **镜头摘要**：前 5 镜，每行一条 32px 高：镜号（等宽两位）· 景别/运镜小标签 · 画面描述单行截断 · 时长。超过 5 镜底部一行「还有 N 镜」，`text-muted-foreground text-xs`。
- **打开编辑**：双击卡片正文打开弹窗（同文本节点）；选中节点时上方功能区（`NodeOverlays`）给一个「编辑分镜」按钮（`Maximize2` 图标），满足「展开编辑」入口。卡片正文上不放说明文字（规范 6.2）。
- **连接点**：左 target（接剧本），右 source（出到图片 / 视频）。非法连线沿用 `canAcceptConnection` 的倾斜反馈拒绝。

### 空状态

卡片正文换成：占位大图标（新增 `StoryboardPlaceholderIcon`，风格同其它 placeholder：三格胶片画格）+ 一句「还没有镜头」+ 按钮「添加镜头」（`variant="outline" size="sm"`，点了打开弹窗并自动加第 1 行、聚焦画面描述）。
迭代 2 在它旁边加「从剧本拆分镜」主按钮，位置已预留（按钮组居中排列）。

弹窗里表格为空时同样：图标 + 「还没有镜头」+「添加镜头」。

## 3. 表格编辑区（弹窗）

### 3.1 结构

```
┌ 标题栏 ────────────────────────────────────────────────────────────┐
│ [图标] 分镜表名称            ┃ 12 镜 ┃ 总时长 01:24 ┃        [×]   │
├ 表头（sticky）──────────────────────────────────────────────────────┤
│ ⋮⋮ │ 镜号 │ 分镜图 │ 画面描述 *     │ 景别 │ 运镜 │ 动作/走位 │ 对白 │ 时长 │ ⋯ │
├────────────────────────────────────────────────────────────────────┤
│ ⋮⋮ │  01  │ [16:9] │ 多行文本…      │ 中景▾│ 推 ▾ │ 多行文本  │ …    │ 3.0s │ ⋯ │
│ …                                                                  │
│ [+ 添加镜头]                                                        │
└────────────────────────────────────────────────────────────────────┘
```

| 列 | 宽度 | 控件 |
|---|---|---|
| 拖拽柄 | 28px | `GripVertical`，悬停行时显示，`cursor-grab` |
| 镜号 | 48px | 只读，两位数 `01`，`tabular-nums font-semibold`，不可编辑（没有输入框外观） |
| 分镜图 | 112px | 16:9 画格 96×54，迭代 1 显示占位（`ImageIcon` 淡色）；迭代 2 接上传 / 生成 |
| 画面描述 | 弹性，最小 240px | 自动增高 textarea，最多 4 行后内部滚动；占位「必填」 |
| 景别 | 104px | 下拉（见 3.3） |
| 运镜 | 104px | 下拉（见 3.3） |
| 动作/走位 | 200px | 自动增高 textarea |
| 对白 | 200px | 自动增高 textarea |
| 时长 | 88px | 数字输入 + 秒单位（见 3.4） |
| 行操作 | 40px | `Ellipsis` 菜单 |

弹窗宽度不够时（< 1100px）表格横向滚动，拖拽柄、镜号、分镜图三列 `sticky left`，保证始终知道在改第几镜。

### 3.2 单元格样式（像电子表格，不像表单）

- 行最小高度 72px（分镜图 54 + 上下留白），行间 1px `border-border/60` 分隔，悬停行 `bg-chrome-hover`。
- 输入框平时**无边框无底色**，只有文字；悬停 `bg-chrome-hover`，聚焦 `bg-background ring-1 ring-node-ring/60`，圆角 `rounded-lg`。这样 50 行时不会满屏框框。
- 画面描述为空：失焦后该格 `ring-1 ring-destructive/50`，占位字「必填」变 `text-destructive/70`；不阻止保存（草稿态），只提示。
- 正在拖拽的行：`shadow-2xl ring-1 ring-node-ring scale-[1.01]`，原位置留一条 2px `bg-primary` 插入线。

### 3.3 下拉控件（景别 / 运镜）

用 `components/ui/select.tsx`，触发器做成无边框单元格样式（同 3.2），右侧小 `ChevronDown`；弹出面板用清透风格 `bg-chrome ring-1 ring-chrome-border shadow-lg backdrop-blur-xl rounded-2xl`，选项行高 36px。

每个选项「中文名 + 右侧英文缩写（`text-muted-foreground text-xs`）」，给不懂术语的人一个锚点，懂行的人一眼认出：

- **景别**：大远景 ELS · 远景 LS · 全景 FS · 中景 MS · 中近景 MCU · 近景 CU · 特写 BCU · 大特写 ECU
  选项左侧一个 16px 小取景框图示（同一个人形在不同大小的框里），一眼看出远近，见原型。
- **运镜**：固定 · 推 · 拉 · 摇 · 移 · 跟 · 升 · 降 · 环绕 · 变焦 · 甩镜 · 手持 · 航拍
  选项左侧 lucide 图标：固定 `Lock`、推 `ZoomIn`、拉 `ZoomOut`、摇 `MoveHorizontal`、移 `ArrowRightLeft`、跟 `Footprints`、升 `ArrowUp`、降 `ArrowDown`、环绕 `RotateCw`、变焦 `ScanSearch`、甩镜 `Wind`、手持 `Hand`、航拍 `Plane`。

只能从枚举里选（AC5），没有「自定义」项。新行默认 **中景 / 固定**，保证这两个字段永远有值。
键盘：聚焦触发器后 ↑↓ 切换、Enter 确认、输入首字（如「特」）跳到对应项（Select 自带 typeahead）。

### 3.4 时长

- 数字输入 + 后缀「s」，`tabular-nums text-right`，默认 3。
- 允许输入时暂时越界，**失焦 / 回车时修正**：小于 1 → 1，大于 60 → 60，保留 1 位小数；空或非数字 → 恢复原值。修正后该格 ring 闪一下 `ring-amber-500/60`（300ms），`title` 显示「时长范围 1–60 秒」。
- ↑↓ 键 ±0.5 秒。

### 3.5 行操作

- **新增**：表格末尾「+ 添加镜头」行（整行宽的虚线按钮，高 44px），点了在末尾加一行并聚焦画面描述。
- **行菜单**（`Ellipsis`，悬停行时显示，键盘可聚焦）：在上方插入 / 在下方插入 / 复制镜头 / ——分隔—— / 删除镜头（`text-destructive`）。
- **复制**：插到原行下方，内容全复制（迭代 2 起关联的图片/视频节点 ID 不复制）。
- **删除二次确认**：点「删除镜头」后菜单原位换成确认小面板「删除第 3 镜？」+「取消」「删除」，不弹全屏 AlertDialog，打断最小。
- **拖拽排序**：只能从拖拽柄拖，避免和文本选择冲突；松手后镜号重排，镜号数字做一次 150ms 淡入，让用户看到「重新编号了」。
- 任何增删改排序后，标题栏「N 镜 · 总时长 mm:ss」立即更新（AC6）。总时长按秒求和后四舍五入到整秒显示，悬停 `title` 显示精确值「共 84.5 秒」。

### 3.6 保存

不加「保存」按钮：每次改动直接写回节点数据（和其它节点一样走画布自动保存 + revision）。文本框为了性能在**失焦时**提交，下拉 / 时长 / 增删排序即时提交。关闭弹窗即完成。

## 4. 性能建议（AC13，给工程师）

- 50 行不需要虚拟列表：行组件 `memo`，按 shot.id 作 key，单格编辑只更新本行；文本框本地 state，失焦才写节点数据，避免每个字触发画布重渲染。
- 超过 100 行再考虑 `@tanstack/react-virtual`（仓库已有），注意虚拟列表和拖拽排序要一起处理。
- 拖拽：仓库没有 dnd-kit，可用已依赖的 `motion` 的 `Reorder.Group` / `Reorder.Item` + `useDragControls`（只从拖拽柄触发）。
- 节点卡片只读前 5 镜做缩略、前 5 镜做摘要，不随表格行数变重。

## 6. 迭代 2：拆分镜与按行生成

> 对应 PRD 6.4–6.6、AC2–AC4、AC7–AC10。原型里用顶部的演示开关切换「剧本已连接 / 未连接」和「拆分会失败」。

### 6.1 「从剧本拆分镜」入口和模型选择

拆分镜有两个入口，用同一套状态（节点功能区里不放拆分镜按钮）：

| 位置 | 形式 |
|---|---|
| 弹窗标题栏右侧 | 清透胶囊：`[模型 ▾ │ 从剧本拆分镜]`，紧挨统计左边；按钮只有文字，没有图标 |
| 空状态（卡片和弹窗） | 主按钮「从剧本拆分镜」+ 次按钮「添加镜头」，左右并排 |

- **模型下拉**：复用短剧那套文本（Agent）模型下拉：`ChipPopover variant="chrome"` + `useRemoteModels("agent")`，逻辑照 `components/drama/agent-model-picker.tsx`（厂商 logo、第一个标「默认」，空值跟随后台默认）。选中的模型记在本机（不进节点数据，免得进撤销栈和导出文件），标题栏和空状态的按钮共用一份。
- **按钮没有图标**：只有文字；拆分中换成转圈的 `Loader2`。
- **没连剧本**：按钮 `disabled`，悬停 `title` / Tooltip「请先连接剧本节点」（这是禁用原因，规范 6.2 允许保留）。模型下拉仍可选。
- **剧本是空的**：同样禁用，提示「剧本节点还没有内容」。
- 连了多个剧本节点时不另做选择，按连线顺序拼接正文（由工程师确认后端是否支持；不支持就只取第一个）。

### 6.2 已有内容时：覆盖 / 追加 / 取消

表格为空直接开始；已有镜头时先弹 `AlertDialog`（小尺寸 `max-w-sm`，常驻挂载）：

```
┌────────────────────────────────┐
│ 分镜表里已有 6 个镜头            │
│                                │
│        [取消] [追加到末尾] [覆盖] │
└────────────────────────────────┘
```

- 标题直接给出现状数字，不加解释段落；按钮文字本身说明后果。
- 按钮：`取消`（ghost）、`追加到末尾`（outline，**默认聚焦**，不丢数据的选项）、`覆盖`（destructive）。
- 覆盖后，被替换的行原来关联的图片 / 视频节点**不删除**，只是解除关联（画布上的东西不会因为一次拆分消失）。
- 覆盖完成后给一个 sonner toast「已覆盖为 8 个镜头」带「撤销」操作，调用画布撤销，兜住误点。

### 6.3 拆分中

拆分是一次文本模型调用，十几秒到半分钟。

- **按钮**：变成 `Loader2` 旋转 +「拆分中」，禁用；模型下拉禁用。
- **弹窗里**：
  - 表头下方一条 2px 不确定进度条（`bg-status-running`，左右往返动画）。
  - 表格为空：空状态换成 3 行骨架行（和真实行同高同列宽，`Skeleton` 闪烁），标题「正在拆分镜」。
  - 表格有内容：整张表 `opacity-60 pointer-events-none`，锁住编辑，免得和即将写入的结果打架；追加模式下在末尾多出 3 行骨架行，告诉用户新镜头会出现在哪。
  - 如果工程师做成流式返回，骨架行逐行替换成真实行即可，不用改设计。
- **节点卡片**：标题行状态槽显示「拆分中」（`text-status-running`，同 `NodeStatusLabel` 的生成中样式），缩略图条闪烁骨架。
- **关掉弹窗不中断**，回来还能看到进度。迭代 2 不做「停止」按钮（PRD 没要求；后端支持取消的话再加）。

### 6.4 拆分完成 / 失败

- **完成**：新写入的行底色 `bg-status-running/8` 停留 1.2s 后淡出，标出哪些是新来的；滚动到第一条新行。标题栏统计实时更新。时长超出 1–60 的已被截断，**不额外提示**（PRD 规定的修正，用户看到的就是合法值）。
- **失败**：表格保持原样。
  - 弹窗开着：表头下方出现一条横幅 `bg-destructive/8 text-destructive rounded-xl`：`⚠ 拆分镜失败：{原因}` + 右侧「重试」按钮 + 关闭 ×。原因直接用后端返回的文案（超时、模型不可用、返回格式不对等）。
  - 弹窗关着：节点标题行状态槽显示「拆分失败」（`text-destructive`，悬停 `title` 显示原因），同时 toast 一条带原因的错误。下次打开弹窗横幅仍在，直到重试或关闭。

### 6.5 分镜图单元格

单元格仍是 96×54 的 16:9 画格。操作全部放进画格：悬停或键盘聚焦时浮出一排 28px 的圆形清透图标按钮（`bg-chrome ring-1 ring-chrome-border backdrop-blur`），每个都有 `title`，不写文字。

| 状态 | 画格显示 | 悬停按钮 |
|---|---|---|
| 空 | 淡色 `Image` 图标 | `Sparkles` 生成分镜图 · `Upload` 上传 |
| 排队 / 生成中（关联节点在跑） | 骨架闪烁 + 居中「生成中 42%」/「排队中」（复用 `NodeStatusLabel`） | `Crosshair` 在画布中定位 |
| 已生成（来自关联图片节点） | 图片 `object-cover`；左下角 16px 小角标 `Link2`，表示来自画布上的节点 | `RefreshCw` 重新生成 · `Upload` 上传替换 · `Crosshair` 定位 |
| 生成失败 | `bg-destructive/8`，居中 `TriangleAlert` + 「生成失败」，`title` 显示原因 | `RefreshCw` 重新生成 · `Upload` 上传 · `Crosshair` 定位 |
| 手动上传 | 图片；无角标 | `Sparkles` 生成分镜图 · `Upload` 替换 · `X` 移除 |
| 上传中 | 图片预览变暗 + 居中「上传中 60%」 | 无 |

- **点击图片本身**：打开现有的 `media-lightbox` 大图预览。
- **拖入上传**：拖着图片文件进入画格时，画格 `ring-2 ring-node-ring` + 内部虚线框 + 居中 `Upload` 图标；拖到同一行的其它位置也算拖到这一格（整行浅色高亮），命中区大一点。非图片文件不高亮、不接收。
- **上传失败**（格式 / 大小 / 网络）：画格回到原状态，toast 显示原因。
- **定位**：关闭弹窗，画布平移到关联节点并选中它（复用 `use-focus-node`），方便用户去改提示词、换模型。
- 关联节点被删除：画格回到「空」，按钮恢复「生成分镜图」（AC8）。
- 点「生成分镜图」后画格立刻进入「排队中」，弹窗不关；画布上的图片节点在弹窗背后创建。

### 6.6 视频列

视频状态要一直看得见（PRD 6.6），所以新增一列「视频」，放在时长和行操作之间，宽 120px。表格最小宽度相应 +124px（约 1340px），弹窗宽度上限放宽到 `min(1400px,96vw)`；行内不放视频预览，只放状态和一个动作。

| 状态 | 显示（状态点 + 文字） | 动作 |
|---|---|---|
| 未生成，未建节点 | — | 小号 ghost 按钮 `Video` +「生成视频」 |
| 未生成，已建节点（节点不自动开始） | 灰点 `bg-muted-foreground` +「未生成」 | 文字按钮「去生成」→ 定位到视频节点，用户在那里确认模型和参数再点生成 |
| 生成中 | 蓝点（呼吸动画）+「生成中 42%」 | 悬停出 `Crosshair` 定位 |
| 已完成 | 绿点 `bg-status-success` +「已完成」 | 点文字打开 lightbox 播放；悬停出 `Crosshair` 定位 |
| 失败 | 红点 +「失败」，`title` 显示原因 | 「去处理」→ 定位 |

- 状态文字和点的颜色沿用 `NodeStatusLabel` 的 token（`text-status-running` / `text-destructive` / `--status-success`），和画布节点标题行一致。
- **重新生成视频**放进行菜单：「重新生成视频」复用同一个视频节点，更新提示词和参考图后定位过去（同样不自动开始）。
- 行菜单同时加「生成分镜图」「生成视频」两项，给键盘用户一条不靠悬停的路径。菜单顺序：生成分镜图 / 生成视频 ——— 在上方插入 / 在下方插入 / 复制镜头 ——— 删除镜头。

### 6.7 时长被适配的提示

视频模型只支持部分时长时，视频节点取最接近值（PRD 6.6）。这一行的时长格下方显示一行 `text-xs text-status-warning tabular-nums`：「实际 5s」，`title` 为「所选视频模型只支持 5s / 10s」（具体可选值按模型）。

- 只在**已建视频节点且实际时长 ≠ 行时长**时出现；行时长或模型改到一致后自动消失。
- 行里改时长**不会**回写已建好的视频节点（PRD：节点上的改动互不回写），所以提示按「节点当前时长」和「行时长」对比得出。

### 6.10 给工程师的实现备注

- 行上要存的关联：`imageNodeId?`、`videoNodeId?`、手动上传的 `imageAssetId?`（三选一显示，上传会清掉 `imageNodeId`）。画格显示的状态从关联节点的 data 实时读，不在行上另存一份。
- 分镜图格和视频格订阅关联节点时用细粒度 selector（只取 status / progress / 结果 src），别让一个节点进度变化重渲染整张表（AC13）。
- 拆分中的锁表、失败横幅的「待处理」状态建议放在节点数据之外（运行时 store），刷新后不用恢复「拆分中」；如果后端任务可对账，再按任务状态恢复。
