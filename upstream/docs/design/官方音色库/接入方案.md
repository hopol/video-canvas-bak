# Seedance 音色库接入方案

> 目标：把方舟 cn-beijing 与 BytePlus 的 Seedance 参考音色接入资产库，可浏览、可试听、可在画布视频节点里作为参考音频。
> 做法：音色就是一条带公网地址的素材，所有模型都按这个地址取用（取舍见 §10）。
> 数据日期：2026-11-19。方舟国内 80 条来自 `seedance.user_assets` 的真实素材，BytePlus 101 条来自公开素材列表；记录随迁移 `0044` 入库，文件在公网地址上（见 §9）。

## 1. 关键事实

| 事实 | 证据 | 影响 |
|---|---|---|
| 数据源是方舟 cn-beijing 的真实音色，不是源项目里残留的 BytePlus 国际站清单 | 本地 `seedance.user_assets` 80 条，音频与缩略图均带方舟官方 asset ID | 入库以这 80 条为准，不能拿 101 条国际站快照冒充 |
| 音色文件有现成的公网地址 | 记录里的 `public_url`（`img.vbing.site`） | 所有模型按这个地址取用：`as=url` 直接传，`as=base64` 由后端下载转码；不需要上游素材 ID |
| 官方音色是系统公共素材，不属于任何用户 | `assets.user_id=0`、`source=official` | 所有人可读可引用，但写操作仍按原归属校验 |
| 现有素材模型没有公网地址 / 缩略图 / 分类字段 | `backend/internal/model/asset.go` 原结构 | 必须加字段，纯导数据做不到 |
| 画布引用条与首页/后台参数面板不是同一套 UI | `TaskPromptPanel` 只渲染 `VideoParamPanel section="params"`，引用走 `RefStrip` | 入口必须挂在 `RefStrip`，只改 `RefCard` 画布里看不到 |

**结论：数据层要扩字段，前端要在画布引用条里补入口，生成链路不用改；记录随迁移入库、文件放在公网地址上，没有额外的导入步骤（见 §9）。**

## 2. 架构

```text
输入：方舟国内 80 条 + BytePlus 101 条公开音色
  │
  ▼
迁移 0044：assets 表加列并写入 181 条记录（source=official, user_id=0）；文件在公网地址（R2 + img.vbing.site）
  │
  ├──▶ 资产页「音色库」tab：缩略图 + 试听（虚拟列表）
  │
  └──▶ 画布视频节点引用条「+」/ 素材库弹框 → 音色库 → params.audios / 角色音色
         │
         └── 所有模型：按素材的公网地址取用（as=url 直接传；as=base64 后端下载转码）
```

### 数据模型（迁移 0044）

在 `assets` 表加列，不建新表（音色分类也并进同一个迁移）：

| 列 | 用途 |
|---|---|
| `public_url` | 音频的公网地址；非空表示文件不在平台存储里，读取直接用它，不走 `storage_id` 和 `/files` |
| `thumbnail_url` | 缩略图的公网地址；空表示没有 |
| `voice_age` / `voice_gender` / `voice_lang` | 音色分类，供筛选 |
| `source=official` | 系统公共音色标记（`user_id=0`） |

官方素材库的 `asset-xxx` 编号已经在 `storage_key` 里（`official-voices/fz-asset-xxx-audio.*`），需要溯源看它即可，不另存一列。

不为音色单独建 `official_voices` 表：音色本质就是「一条 audio 素材 + 一张缩略图」，复用现有素材体系即可；新表只会制造并行模型。

## 4. 运行环境变更

- 本地开发库如果之前登记过 `doubao-video@1.3.0`（旧方案的 `filed` 音频标记），插件代码已回到 1.2.1，需要在后台重新同步插件版本，必要时把模型发布配置对齐到 1.2.1。
- 官方音色数据：方舟国内 80 条 + BytePlus 101 条，各带一张缩略图；记录由迁移 `0044` 写入，文件在公网地址上，不需要手动导入。
- 运行中的后端 Registry 缓存最多 30 秒自动刷新；无需为了这一步重启服务。

### 4.1 备案（filing / asset://）的适用边界

**虚拟人像库备案只适用于方舟 Seedance 与 BytePlus 渠道，其他视频模型不适配。** 判据是渠道 base_url，不是显示名：

| 渠道 key | 显示名 | base_url | 备案能力 |
|---|---|---|---|
| `a5e7a7f7…` | seedance-ark-cn | `ark.cn-beijing.volces.com` | 方舟国内站，已配 `filing_json`（zhongzuo 素材组） |
| `f4842494…` | seedance | `ark.ap-southeast.bytepluses.com` | BytePlus 国际站，具备备案能力（当前未启用） |
| `f4cf11d6…` | agnes-ai-intl | `apihub.agnes-ai.com` | 不适配，`filing_json={}` |
| 其余 | deepseek / claude / image | — | 不适配，`filing_json={}` |

- 备案配置是**渠道级**的：`ai_channels.filing_json`（`{enabled, group_id, project_name}`）+ `ai_secrets` 里的 AK/SK。它不属于模型，不能写进模型 `capabilities`。
- `filed: true` 只出现在 Seedance 用的 `doubao-video` 插件的**图片**引用上（真人库备案图换成 `asset://`）；音频引用不带它，所有模型的参考音频都是普通 `{__fileRef, as:"url"}`，宿主走 `Assets.Open` / 公网地址取音频文件。这条分流由**插件是否声明 filed**决定，不是模型名。

### 4.2 故障复盘：模型 capabilities 里的错位 filing 导致 3 个 Seedance 模型下线

- **现象**：真实模型清单 `GET /models?kind=video` 只返回 1 个 Seedance（`m-d685fa4ef23d`），另外 3 个在画布里判定 offline、无法选中/无法用音色。
- **根因**：3 个模型的 `capabilities` 里有一个非法字段 `filing`（`{enabled, group_id, project_name, site}`，是渠道级备案配置的副本）。`modelcfg.ParseModel` 的字段白名单没有 `filing`（只有 context/ops/params/prompt/prompt_format/refs/system/video/vision），整模型被 `buildState` 忽略。日志 `ai_config_registry.go:154`「已启用的模型配置无法解析，已忽略」有明确记录。
- **非本次升级引入**：`filing` 在 revision 1（doubao-video 1.1.0 时代）就存在，1.3.0 升级只改了协议版本号。幸存模型 `m-d685fa4ef23d` 恰好没有该字段。
- **修复**：为 3 个模型各新增 revision 3，从 `capabilities` 删除 `filing` 并发布；revision 1/2 原样保留可追溯（原 filing 值见 rev2 或国内方舟渠道 `filing_json`）。修复后清单恢复 4/4，Registry 刷新后日志零报错。
- **判据**：排查「模型清单里少模型/画布 offline」先看 `ai_config_registry.go:154` 日志，别只看 `ai_models.enabled`；启用状态与能否进清单是两件事。

## 5. 不做的事

- 不把官方音色复制成每个用户的个人资产：会制造副本和归属问题，系统公共素材 + 引用即可。
- 不使用国际站 101 条快照冒充国内方舟资源。
- 不做 `asset://` 引用：不记官方素材 ID、不分资源域、渠道上不加声明字段（取舍见 §10）。
- 不让普通用户通过 API 写 `source=official` 素材；写操作仍走用户归属校验。
- 不把导入做成后端 API 或后台按钮：它是部署步骤，只在命令行跑，避免普通用户触发重复写入。

## 6. 验收标准

1. `GET /assets/official?kind=audio` 返回 181 条（分页上限 100，前端按页取全量），每条带可用缩略图与音频地址。
2. 资产页「音色库」能看到缩略图，点开能试听。
3. 画布视频节点引用条「+」→「音色库」能选音色；选中后 `params.audios` 含该素材 ID，当前方式不支持音频时自动切到「全能参考」。
4. 所有模型（含 Seedance）生成请求里参考音频都是音色的公网音频地址（或按 `as=base64` 转码）。
5. 素材库弹框（角色卡「绑定已有」音色、画布音频节点填空）切到「音色库」能看到 181 条紧凑小卡（虚拟列表，只挂载视口附近的卡片），可勾选；选中后写进角色的 `voice.assetId`（片场/画布生成时随角色带入 `audios`）。
6. `bun test` 与后端检查通过；新环境跑完迁移后，`GET /assets/official?kind=audio` 返回 181 条。

## 7. 片场与角色卡：音色的真正去向

音色在生成链路里只有一条入口：`input.audios`（素材 ID 数组）。片场（短剧 studio）没有单独的音频选择控件，它的参考音频完全来自**角色卡音色**——`character.voice.assetId` 经 `characterRefsOfNode` → `resolveBindings` 展开进 `audios`（见 `web/src/utils/tasks/capabilities.ts`、`web/src/utils/drama/segment-input.ts`）。所以「角色能绑定 音色库」等价于「片场能用 音色库」，不需要在片场另做入口。

角色卡音色是画布节点里的一个引用（`{mode:"audio", assetId, src, origin}`，见 `web/src/types/canvas.ts` 的 `CharacterVoice`），没有独立的后端角色表。官方音色作为 `source=official` 的公共素材，按 ID 可被任意用户读取，写进 `voice.assetId` 后生成时由后端按这条素材的公网地址交给各模型。

「绑定已有」音色现在走统一的 `AssetPickerDialog`，来源含「音色库」（紧凑网格，一行多列），与画布音频填空共用同一实现。

## 8. 分类：语言（大类别）+ 人群（子类别）

界面上两级：**大类别是语言，子类别是人群**。两者都不是人工猜的：

| 类别 | 取值 | 数据来源 |
|---|---|---|
| 大类别 · 语言 | 中文 / English | **以每条音色自己的 `voice_lang` 为准**（见 `voiceLangOf`）：BytePlus 全是英文，方舟国内默认中文，其中 7 条英文声音（Chucky、Clown Man、Jigsaw、Kevin McCallister、Noah、Xavier、Zayne）人工标成 `en` |
| 子类别 · 人群 | 男孩 / 女孩 / 男生 / 女生 | 官方素材库标签「年龄-性别-名字」：方舟国内 80 条按官方素材 ID 一一对齐（迁移里已展开成逐行的取值）；BytePlus 101 条名字本身就是 `Age - Gender - Name`，直接拆 |

- 数据落在素材表：`voice_age`（child / teen / young / middle / older）、`voice_gender`（male / female）、`voice_lang`（zh / en），随迁移 `0044` 一起写入，181 条无一遗漏。
- 归类规则（`utils/assets/official-voices.ts`）：`child`、`teen` 两个年龄段算童声 → 男孩 / 女孩；`young`、`middle`、`older` 算成人 → 男生 / 女生。年龄仍完整存在数据里，以后想细分（例如单独筛「老年」）加一档即可。
- 语言直接读每条音色的 `voice_lang`：方舟国内那套并不全是中文声音（有 7 条英文角色），按来源一刀切会让「中文」里混进英文；没有 `voice_lang` 的素材（非公开音色）只在「全部」里出现。官方没有语言字段，这 7 条是人工判断的，以后出现别的英文声音也只能人工改这一列。
- 方舟国内有 7 条导入时名字被截短（`小何2.0` → `小何`、`温柔女神` → `温柔女神2`），其中一条被写成占位名 `premium-default-avatar`（实为 `少年_少女-男-炀炀`，`asset-20260224190657-bj5zq`）。迁移按 asset ID 修正分类并顺手改回名字——**分类只能按 ID 对，不能按名字对**。
- 展示：卡片角标显示子类别（男孩 / 女孩 / 男生 / 女生），BytePlus 的显示名去掉「Age - Gender - 」前缀（`voiceDisplayName`），信息不重复。

## 9. 数据分发（2026-11-20 补充）

**问题**：PR #90 最初只带代码和迁移，181 条音色的记录与文件都不在仓库里，迁移全是「按已有行回填」，
新环境跑完迁移后 `source=official` 是 0 条——音色库页面空白，生成时也没有可选音色。
根因是**数据没有可复现的分发路径**：记录只存在于某台机器的库里，文件只存在于那台机器对应的存储里。

**做法**：记录随迁移入库，文件放在公网地址上，两者都不需要人工导入。

| 层 | 位置 | 说明 |
|---|---|---|
| 记录 | `backend/migrations/0044_official_voices.sql` | 加列并插入 181 条音色（音频 + 缩略图合成一行），地址前缀只在 INSERT 里写一处 |
| 文件 | Cloudflare R2 桶 `video-canvas` 的 `official-voices/` 文件夹下 | 362 个文件（181 音频 + 181 缩略图），通过桶绑定的域名 `img.vbing.site` 读取，不进仓库；与用户素材分开存放 |

**读取方式**：

- 页面试听、缩略图直接用 `public_url` / `thumbnail_url`，不经过 `/files`，也不依赖默认存储配置。
- 生成时给上游的是 `public_url`：`as=url` 直接用公网地址，`as=base64` 由后端按 URL 下载后转码（`AssetService.Open` / `fetchPublicAsset`）。公网地址取不到按「素材不存在」处理。
- 缩略图不再单独成行（取消 `source=official_thumb`），也去掉了只作溯源且无人读取的 `official_channel_key` 列；后来又去掉了只服务 `asset://` 的 `official_asset_id`、`official_scope` 两列。

**取舍**：

- 文件放公网而不是进仓库：省掉 41 MB 的素材包和手动解包、同步存储的步骤；代价是依赖这个公网地址长期可用。
- 用桶绑定的自定义域名 `img.vbing.site`（走 Cloudflare CDN 缓存），而不是 r2.dev 地址（限速、无缓存）。
  桶的 CORS 规则允许 `canvas.vbing.site` 与本地开发地址，画布里音频波形的 `fetch` 才不会被拦；
  从其他域名访问的页面波形会退化成圆点（前端已兜底，不报错），试听与缩略图不受影响。
- 官方音色放在 `official-voices/` 专属文件夹，与桶里用户素材分开；以后换域名新增一个迁移替换 `public_url` / `thumbnail_url` 的前缀即可。
- 记录里的 `storage_key` 保留对象 key，只用于唯一性与溯源，不用于读取。

## 10. 取舍记录：不用 `asset://`（2026-11-21）

**旧方案**：Seedance 走方舟官方素材 ID（`asset://<ID>`），其他模型走音频 URL。为此建了一整套东西：插件 `doubao-video` 1.3.0 给参考音频标 `filed`、
`FiledAssetResolver` 的官方音色分支、`assets.official_asset_id` / `official_scope` 两列、渠道上的 `voice_scope` 声明（含校验、更新、快照、模型清单透出）、
`provider/scope.go` 的资源域判定、后台渠道弹窗的「公开素材资源域」、分镜里的跨域提示。约 600 行生产代码、340 行测试。

**为什么砍掉**：音色本身已经是一条公网 URL，所有模型都能直接取用；`asset://` 只是 Seedance 多一种引用形态，却带来了资源域、渠道声明、跨域回退一整套判定，
配置出错还会让生成静默退化。URL 一条路径更简单，行为也一致。

**前提**：Seedance 接受这些公网地址作为参考音频。这一点需要实测确认；如果 Seedance 实际拒绝，再按本节的旧方案补回，不要在现有路径上堆判定。

**随之删除**：`assets.official_asset_id`、`official_scope`、`ai_channels.voice_scope`；`ModelInfo.voice_scope`；`FiledAssetResolver` 的官方音色分支与 `OfficialAssetSource`；
`doubao-video` 插件回到 1.2.1；前端的 `scope` / `officialAssetId` 字段、资源域标签、分镜跨域提示、后台渠道的资源域表单。
迁移 `0044` 尚未发布，直接改它而不是新增迁移；已经跑过旧版本的开发库需要重建。
